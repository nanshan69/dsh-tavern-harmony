# 故障排查

## 先跑体检

```bash
python3 scripts/doctor.py
```

七组检查（包 / profile 登记 / 依赖 / preset / 核心补丁 / 运行时 / 数据），
红叉优先处理，黄色警告多数不影响使用。

## 日志在哪

| 文件 | 内容 | 关键行 |
| --- | --- | --- |
| `$DSH_HOME/tavern-load.log` | host 加载进度 | `IMPORT FAILED` / `APPLY FAILED` / `jsdom require failed` |
| `$DSH_HOME/tavern-worker.log` | 模板 worker 步骤 | `init:` / `step:` / 超时 |
| `$DSH_HOME/tavern-script-worker.log` | 脚本 worker | 同上 |
| `$DSH_HOME/tavern-boot.json` | 开机健康标记 | `attemptAt` 有、`okAt` 没有 = 上次启动被卡过 |
| DSHM 自己的 host 日志 | 启动期报错 | 搜 `tavern` / `home 层预检` |

前端（ArkWeb）的报错在浏览器控制台；`/api/tavern-gate/status` 可以直接 curl。

## 症状 → 处理

### 重启后没有左下角按钮

1. `doctor.py` ②：`dsh-tavern-gate` 是否在 bundles 里、是否启用。
2. 设置 → 插件 里该插件是否被停用。
3. 仍没有：手动 `curl http://127.0.0.1:3120/api/tavern-gate/status`；
   404 = gate 没加载（bundle 未生效或 Host 没重启）。

### 点「酒馆：关」后一直「正在加载…」

按钮会把状态改成「正在关闭…/正在加载…」并等接口返回。超过十几秒说明 `toggle`
卡住了，通常是 host 的 `apply()` 在等某个服务。看 `tavern-load.log` 最后一行：

- 停在 `load .../lib/xxx.js` → 某个模块导入卡住（多半是依赖缺失或 worker 初始化）
- `jsdom require failed` → 依赖没装好（`doctor.py` ③）
- `IMPORT FAILED after 90000ms` → 90 秒超时兜底生效，Host 还活着，但酒馆没起来

### 正文重复、空白、或「服务端模板显示处理失败」

模板引擎失败。依次看：

1. `tavern-worker.log` 是否有 `init:` 之后的 `step:`；没有 → worker 没起来。
2. `doctor.py` ③ 的 `jsdom` 是否为绿。
3. 报错里出现 `模板 RPC 超时（30 秒未返回）` → 模板渲染确实太慢，
   常见于超长上下文或超大世界书；先 `/compact` 再试。
4. 错误是 `服务端提示词模板执行已停止` → 多半是酒馆被卸载（`dispose`）时
   取消了正在跑的渲染；重新打开酒馆即可，不会损坏数据。

### 候选行动 / 生图一直「生成中」

1. `doctor.py` ⑥：门是否在运行。
2. 任务记录里的 `status` 卡在 `running` 超过 15 分钟会被自动判失败（移植里加的
   陈旧守卫）；重试一次通常就好。
3. 前端 `submitTask` 超时已放宽到 15 秒；如果仍失败，看 Host 日志里的
   `submitTask` 报错。

### 生成了图但没有保存

`scene-images/<hash>/diagnostics.json` 里 `recovery: "save"` 表示「图已生成、
保存被取消」。移植里会在下次轮询该会话时自动补保存；也可以在该会话里重新生成。
`failure: "aborted"` + 时长恰好 300s = 旧版本的 5 分钟超时（已改 15 分钟）。

### 酒馆会话在原生界面打不开（格式错误）

`assistant/message embeds its source stream...` —— 只读会话补丁没装。

- 检查 `curl /api/tavern-gate/session-patch-client` 的 `status` 字段；
  `missing` = 补丁模块都没导入（`dsh-tavern-host/lib/domain/host-session-patch.js` 缺失？）
- 检查是否设了 `DSH_TAVERN_BOOT_PATCH=0`
- 补丁装上了但前端没应用：刷新页面；看前端控制台有没有 eval 报错

### 启动卡死（打开 DSHM 后界面不出现）

DSHM 的 home 层预检会隔离坏引用，通常等 10 秒能进。仍然不行：

1. 强制停止应用，再开。
2. 让 DSHM 别加载酒馆：编辑 `$PROFILE/package.json`，从
   `dsh.profile.bundles` 里删掉 `dsh-tavern-gate`，再启动。
3. 进去后跑 `doctor.py` 看哪一项坏了。

`tavern-boot.json` 里 `attemptAt` 更新了但 `okAt` 没更新，说明上次启动时
事件循环 1.5 秒内没跑起来 —— 与门或它的依赖有关（最常见是依赖树缺包）。

### 报错对照表

| 报错 | 含义 | 处理 |
| --- | --- | --- |
| `spawn /system/bin/appspawn EACCES` | 端侧不许 fork | 不应出现；出现说明补丁没生效（用了上游原始 `lib`） |
| `createRequire(...).resolve.paths is not a function` | 缺 CJS 兜底 | 确认 `dsh-tavern-host/index.js` 是移植版壳 |
| `ERR_INTERNAL_ASSERTION: Unexpected module status 3` | 用 ESM import 加载真 jsdom | 必须 `createRequire('jsdom')`，见壳里的探针 |
| `WebAssembly is not defined` | worker 里没桩 | 用了上游原始 worker |
| `tool result pruner ...` / 上下文越用越多 | 压缩阈值 | 酒馆会话 `/compact`，或调 preset 的 `thresholdRatio` |
| `tools.restrict() names unknown global tool "web_search"` | preset 缺 `tool-web` | preset 渲染不对，重跑安装器 |

## 紧急回滚

```bash
python3 scripts/uninstall.py --apply          # 摘掉代码与登记，保留数据
# 或只摘登记：
#   编辑 $PROFILE/package.json，删除 dsh-tavern-* 五个 bundle 行
# 然后完全重启 DSHM
```

安装器每次写入都会把 profile `package.json` 备份到
`$DSH_HOME/_tavern-harmony-backup/<时间戳>/`，可以直接拷回去。

数据不会因为卸载丢失；真要清空再手动删 `profile-data/tavern/`。
