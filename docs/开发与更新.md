## 跟进上游新版本

上游用 `dsh-tavern-runtime.json` 的 `revision` 标识每次发布。流程：

1. **拿新产物**：下载上游仓库对应 commit 的 `tavern-plugin/lib/**`、
   `tavern-plugin/prompts/**`、`tavern-plugin/packages/dsh-image-gen/**`、
   `tavern-plugin/packages/dsh-tavern-card-memory/**`、前端 `client.js`。
2. **先看 diff 再动手**：
   ```bash
   diff -ru old/lib new/lib | less
   ```
   重点看我们改过的 12 个文件 + 3 个新增文件是否被上游重写。
3. **优先重放补丁**：在新产物上 `git apply --check patches/upstream/0002-*.patch`；
   能干净应用就用，失败则逐文件手工重放（用 `patches/` 里的 diff 当 checklist）。
4. **前端**：`client.js` 的 4 处改动很小，按 `patches/upstream/0001-*.patch`
   在新 bundle 上重新定位锚点（前缀都是稳定的代码片段，见补丁上下文）。
5. **重生成补丁**：把新的 old/new 跑一遍 diff，覆盖 `patches/`。（生成脚本思路：
   对每个改动文件做 `unified_diff(fromfile='a/...', tofile='b/...', n=4)`。）
6. **更新元数据**：`NOTICE.md` 的上游版本与 revision、`package.json` 的
   `dsh.harmony.upstream*`、各包版本号后缀（`-dshm.N`）。
7. **验证**：安装 → 重启 → 打开酒馆 → 跑一轮：正文、候选、世界书、生图、
   改卡、`/compact`；再跑 `doctor.py`。

## 改前端 bundle

`client.js` 是上游 `node bin/build-tavern-client.mjs` 的产物。本移植没有在设备上
重建它的能力（没有 node 可执行文件，2MB bundle 的打包器也跑不动），
所以做法是「上游构建 + 定点修改」：

- 改之前先 grep 锚点，确认是**唯一**匹配；
- 每次只加最少代码，保持与上游同缩进；
- 改完对比文件大小，确认只变了预期字节数；
- 更新 `patches/upstream/0001-tavern-client-dshm.patch`。

四个已知改动点（详细见补丁）：

1. `factory: (require) => {` 之后插入门守卫（同步 XHR）。
2. `submitTask` 的 `setTimeout(..., 2000)` → `15000`。
3. `betterSidebar.registerTab` 里加「场景生图」页。
4. `confirmSessionPatch` 在补丁已存在时补发握手。

## 改 host lib

`lib/**` 是 vendored 产物，直接改可以，但必须同步补丁，否则下次升级会丢。
建议顺序：改 → 在本机验证 → `diff -u` 出补丁 → 更新 `patches/upstream/0002-*.patch`
→ 更新 `NOTICE.md` 的改动摘要。

## 本地验证清单

| 项 | 怎么验 |
| --- | --- |
| 开关链路 | 关 → 开 → 关，每次页面刷新；`/api/tavern-gate/status` 与预期一致 |
| 重启默认关 | 完全退出再开，按钮是「关」，`loaded:false` |
| 会话可读 | 关闭状态打开一个酒馆会话，能看、能编辑、能重试 |
| 模板 | 发一句正文，`tavern-worker.log` 有 `step:`，正文不是空白 |
| 候选 | 点一次「生成候选」，15 秒内出结果或给出明确错误 |
| 生图 | 配好渠道，触发一张；`diagnostics.json` 不是 `aborted` |
| 体检 | `doctor.py` 全绿 |

## 发布清单

1. 跑一遍上面的验证清单；
2. 改版本：根 `package.json`、各包 `version`；
3. 更新 `NOTICE.md`（上游 revision）与 `docs/`（有行为变化时）；
4. 重新生成 `patches/`；
5. 打 tar（可选）：
   ```bash
   tar --exclude='node_modules' --exclude='*.bak*' \
       -czf dsh-tavern-harmony-1.0.0.tar.gz dsh-tavern-harmony/
   ```
6. 提 tag / 发 release，正文里写「支持的上游版本 + DSHM 版本」。

## 约定

- 不把 `@deepseek-ai/*` 复制进 profile，也不写进仓库；
- 不把 `node_modules` 提交进仓库；
- 所有对上游产物的改动都要能落到 `patches/`；
- 涉及路径的配置一律在安装时渲染，仓库里只放模板。
