# 架构

## 进程与加载边界

DSHM 在端侧把一个 DSH Host 跑在**应用进程内**（没有独立 node 可执行文件，
`process.execPath` 是 `/system/bin/appspawn`，spawn 它会被系统拒绝）。
ArkWeb 里的前端通过 `http://127.0.0.1:3120` 连这个 Host。

```
┌──────────────────────────── DSHM 应用进程 ────────────────────────────┐
│                                                                       │
│  Host（Node 24 · jitless）                    ArkWeb（前端）           │
│  ├─ @deepseek-ai/* 核心                        ├─ 原生聊天界面         │
│  ├─ dsh-tavern-gate   ← 开机加载               ├─ dsh-tavern-gate/client
│  ├─ dsh-better-sidebar                        └─ dsh-tavern-plugin/client
│  ├─ dsh-dream-skin                                    │               │
│  ├─ dsh-tavern-plugin（空 host 行）                    │ HTTP          │
│  ├─ dsh-tavern-remote（typert 启动行）                 ▼               │
│  ├─ dsh-tavern-presets（preset 登记）     /api/tavern-gate/*          │
│  └─ dsh-tavern-host  ← 点「开」时才 import                            │
│        └─ worker_threads：服务端模板引擎（jsdom + ST 模板）            │
└───────────────────────────────────────────────────────────────────────┘
```

关键点：

- **启动配置里没有酒馆 host 行**。`dsh-tavern-gate` 是唯一开机执行的酒馆代码，
  它只注册两条路由、装一份只读补丁，然后等 HTTP 开关。
- 点「开」时 gate 在自己的 cordis fiber 下 `ctx.plugin()` 挂载 `dsh-tavern-host`，
  所以 `dispose` 一次就能把酒馆的回合、后台任务、事件、路由全部卸掉。
- 前端 bundle 的加载行（`dsh-tavern-plugin`）是启动行，但它的 `client.js`
  第一件事是同步问 `/api/tavern-gate/status`；门没开就直接返回空实现。
  因此「关闭」= host 不加载 + 前端不执行，只剩一个按钮。

## 组件职责

| 组件 | 半边 | 职责 |
| --- | --- | --- |
| `dsh-tavern-gate` | host + client | 开关、只读会话补丁、面板样式修正 |
| `dsh-tavern-host` | host | 酒馆本体：会话/回合、人物卡、世界书、正则、MVU、候选、结算、生图、模板 |
| `dsh-tavern-plugin` | client（+ 空 host 行） | 酒馆 UI bundle 的加载行 |
| `dsh-tavern-remote` | host + client | 把 `tavernSessionSignals` 通过 typert 暴露给前端（`follow` / `control` 流） |
| `dsh-tavern-presets` | host（配置） | 两个 agent preset 的子插件行 |

### 为什么是 5 个包

- 前端入口按**包**扫描（`dsh.client`），一个包只能有一个 client 模块 →
  酒馆 UI 和开关必须分开。
- `dsh-tavern-remote` 是 `typert` 远程服务，必须是 bundle 启动行才拿得到
  typert 的注册时机 → 不能塞进按需加载的 host。
- 酒馆 host 有 40MB 运行时（`lib/vendor` 里有 MVU、ST 模板引擎、宏解析器），
  塞进开关包会让「开机只加载 200 行」这个前提失效。

## 生命周期

### 启动

1. `dsh-tavern-gate/index.js` 求值：安装 `@deepseek-ai/*` 解析钩子，
   写开机标记 `$DSH_HOME/tavern-boot.json`。
2. `apply()`：导入 `dsh-tavern-host/lib/domain/host-session-patch.js`，
   给 `SessionEventStream` 装**只读**补丁（让酒馆会话在原生界面可读）。
3. 注册 `/api/tavern-gate/{status,toggle,session-patch-client}`。
4. 前端加载：`dsh-tavern-gate/client.js` 画左下角按钮；`dsh-tavern-plugin/client.js`
   问一次 status，门没开则整包空实现返回。

### 打开酒馆（POST `/api/tavern-gate/toggle?on=1`）

1. gate `import('./tavern-host-entry.js')` → 转出 `dsh-tavern-host`（ESM 壳）。
2. 壳安装解析钩子 / CJS 兜底、探针 `require('jsdom')`、`import('./lib/index.js')`。
3. 酒馆 `apply()`：读 `profile-data/tavern/**`、注册自己的 HTTP 路由、provide
   `tavernSessionSignals`（挂在 `ctx.root`）、启动后台协调器。
4. gate 等 `fiber.await()` + 500ms，让依赖 `tavernSessionSignals` 的
   `dsh-tavern-remote` 行落定，再返回。
5. 前端 `location.reload()`：这次 status 是 `loaded:true`，酒馆 UI 正常挂载。

### 关闭酒馆（`?on=0`）

`fiber.dispose()`：酒馆的 `ctx.effect` 全部回滚（路由、定时器、worker、后台任务），
`tavernSessionSignals` 从 root 撤销，remote 行转 pending。前端刷新回原生界面。

### 一个正文回合（简）

```
用户输入 → 酒馆 assembleSystemPrompt（世界书/角色/正则/变量）
        → 模板引擎渲染（worker_threads，前台优先）
        → 调模型（核心 @deepseek-ai/dsh-llm-deepseek）
        → 流式正文 → 前端 tavern-state 更新（经 dsh-tavern-remote）
        → 回合结束：调度显示同步 / 后台结算 / 候选生成 / 场景生图（都不阻塞正文）
```

## 端侧改写的三个支点

1. **解析**：`registerHooks` 把第三方包里的 `@deepseek-ai/*` 指回核心目录；
   `Module._resolveFilename` 兜底补 `resolve.paths` 缺失。见 `packages/dsh-tavern-gate/index.js`
   与 `packages/dsh-tavern-host/index.js`。
2. **执行**：模板引擎从 fork 改成 `worker_threads`，WebAssembly 打桩，
   CPU 上限 1.5–2GB，超时 + 重试 + 前台抢占。
3. **加载时机**：registry/compaction 用「运行时加载」，避免任何酒馆代码进启动配置。

## 数据

| 路径 | 内容 |
| --- | --- |
| `$DSH_HOME/profile-data/tavern/` | 人物卡、聊天、会话映射、设置、生图记录、插件数据 |
| `$DSH_HOME/profile-data/tavern/scene-images/<hash>/` | 场景图与请求诊断 |
| `$DSH_HOME/tavern-boot.json` | 开机健康标记 |
| `$DSH_HOME/tavern-load.log` | host 加载进度（卡住时看这个） |
| `$DSH_HOME/tavern-worker.log` | 模板 worker 的步骤日志 |
| `$DSH_HOME/tavern-script-worker.log` | 脚本执行 worker 日志 |

数据目录与原生会话互不影响：酒馆会话在 `sessions.json` 里映射到 DSH 会话 id，
正文以酒馆格式落在 `chats/`；原生界面读这些会话时靠只读补丁兼容。
