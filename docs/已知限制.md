# 已知限制

按「会不会影响正常使用」排序。数字来自本机（HarmonyOS PC 档）实测，别的设备会不同。

## 性能

- **首字延迟**：正文第一个字通常要等 5–20 秒，取决于世界书体积、模板复杂度、
  上下文长度和模型。原因不是网络，是端侧 jitless 的模板渲染本身贵。
  会话越长越慢（历史要重新渲染）。
- **模板渲染抖动**：偶发单次渲染 1–2 秒（GC / 其它后台任务抢 CPU）。
  移植里做了前台抢占与排队取消，但设备很忙时仍能看到。
- **后台任务慢**：候选行动、改卡、结算、生图规划都是排队跑模板，
  正文回合进行中会主动让路，所以体感上「要等一会儿」。这是设计取舍，不是卡死。
- **上下文**：1M 窗口的模型在默认 `thresholdRatio: 0.8` 下几乎不会自动压缩，
  会话会一路变慢。两个 preset 里已改成 `0.5`；标准模式（非酒馆）没改，
  需要时手动 `/compact`。

## 生图

- 需要自己配渠道：`novelai`（含第三方中转，如 `https://latent.moe/api/novelai`）、
  `comfyui`、OpenAI 兼容等。没配渠道时只会生成规划文本，不会出图。
- 全流程是异步的：**规划 → 提交 → 轮询 → 保存**，端到端几十秒到十几分钟。
  中途取消（切走、关闭酒馆、重启）会中断；已经生成但没保存的图会在下次打开该会话时
  尝试自动补保存。
- 图存在 `$DSH_HOME/profile-data/tavern/scene-images/<hash>/`，不进相册。
- ComfyUI 渠道要求设备能直连你的 ComfyUI 地址；云端工作流需要能访问相应 API。

## 界面

- 侧栏、候选行动、底部状态面板在 **1 屏 / 2 屏折叠**下是浮层，主题（dream-skin）
  的半透明背景会让下面文字透上来 —— 移植里用 gate 注入的 CSS 强制不透明，
  但只覆盖酒馆自己的面板；其它插件的浮层可能仍有透明问题。
- 手机档（很窄）能用，但候选卡与侧栏比较挤，没有做专门的单屏布局。
- 酒馆的空对话起始页原本有一个大 logo 挡住聊天区，移植里隐藏了它
  （`dsh-tavern-gate/client.js` 里一段 CSS，可删）。

## 数据与兼容

- 人物卡、聊天、世界书都在 `profile-data/tavern/`，**卸载默认不删**。
  升级/重装前建议整体备份这个目录。
- 会话是「酒馆格式 + DSH 会话」双份：酒馆写入的 `assistant/message` 需要只读补丁
  才能在原生界面打开。把 `DSH_TAVERN_BOOT_PATCH` 设为 `0` 会让这些会话在原生界面
  报格式错误（这是有意的取舍）。
- 上游的导入工具（SillyTavern 迁移、novel-to-chat 等 CLI）没有搬进来；
  需要那些功能得在电脑上用上游仓库。

## 安装与更新

- 依赖（约 300MB）不随仓库分发，需要在设备或电脑上装（见 `安装.md`）。
- 上游换版本后，本仓库的补丁大概率打不上：`lib/**` 是**整份 vendored** 的
  上游产物，升级 = 重新把补丁移植到新产物（见 `开发与更新.md`）。
- 没有桌面端的「一键更新」；更新靠覆盖目录 + 重跑安装器。
- 不属于本移植的 `dsh-better-sidebar` / `dsh-dream-skin` 由各自作者维护，
  它们升级可能改变类名，导致 gate 注入的样式失效（表现：面板又变半透明）。

## 明确不支持

- 原生模块（`.node`）：端侧沙箱受签名管辖，装不了也 `dlopen` 不了。
- 桌面启动器、端口管理、多实例：DSHM 单进程单实例。
- 酒馆的「插件市场」里安装**第三方酒馆插件**：能装（数据目录里的 JS 插件），
  但它们如果在宿主侧 `require` 原生模块就会失败。
