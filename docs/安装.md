# 安装

## 方式 A：贴链接安装（推荐）

1. DSHM → 设置 → 插件 → 「安装插件」，贴：

   ```
   github.com/nanshan69/dsh-tavern-harmony
   ```

   也可以让 Agent 执行：`pnpm add github.com/nanshan69/dsh-tavern-harmony`。

2. 安装器会下载仓库（约 45MB）并按根 `package.json` 的 `dependencies`
   拉依赖（jsdom、better-sidebar 等）。等它报成功。
3. **完全退出 DSHM 再打开**。
4. 首次启动，根包 `index.js` 会执行自举：
   - 把 `packages/` 里 5 个包复制进 `$NM/`
   - 内置主题 `vendor/dsh-dream-skin` 复制进 `$NM/`
   - 依赖若被装在本包自己的 `node_modules` 里，链接到 `$NM/`
   - 渲染 preset、补 home patch、把 bundles 改成 6 条正常行，并移除自举行
   - 直接加载 `dsh-tavern-gate`，所以**这次启动**左下角就有「酒馆：关」
5. 之后再重启一次，就完全是普通安装形态。
6. 仓库里的 `packages/dsh-tavern-gate/skills/` 会被铺到 `$DSH_HOME/skills/`（自举那次和以后每次启动都会
   校验一次，幂等）。技能列表见 README 的「内置技能」。

> 日志：`$DSH_HOME/tavern-bootstrap.log`；标记：`$DSH_HOME/tavern-harmony-boot.json`。
> 自举失败不会阻断启动（只会在日志里留 `BOOTSTRAP FAILED`），可以用方式 B 兜底。

## 方式 B：脚本安装

### B-0. 前置

- DSHM 已安装，能正常聊天（Host 与 ArkWeb 都在跑）
- 设备上有 Python 3.11+：DSHM 的 Host 提供了 `python3` 垫片，也可以让 Agent 执行
- 磁盘：仓库约 45MB，`node_modules` 依赖约 100MB（方式 A 已装过就不必重复）

路径约定（下文用变量）：

```bash
DSH_HOME=/data/storage/el2/base/haps/entry/files/dsh/home
PROFILE=$DSH_HOME/profiles/ondevice
NM=$PROFILE/node_modules
CORES=$DSH_HOME/../cores/<当前核心版本>
```

## 1. 依赖（方式 B 需要）

酒馆 host 的 `lib/` 需要下面这些包（`jsdom` 最重要，模板引擎全靠它）：

```
jsdom@26.1.0  marked@16.3.0  yaml@2.9.0  acorn@8.15.0  chevrotain@^11.2.0
@jsquash/jpeg@1.6.0  @jsquash/png@3.1.1  @jsquash/webp@1.5.0
mathjs@12.4.3  ws@8.21.3  zod@^4.4.3
```

三种装法，任选一种（方式 A 贴链接安装时，安装器会按 `dependencies`
自动拉这些包，通常不用手动做）：

### 装法 1：端侧插件通道（需要网络）

DSHM 的 `pnpm` 是假壳，会转成 Host 进程内安装。逐个装到 profile：

```bash
pnpm add jsdom@26.1.0
pnpm add marked@16.3.0 yaml@2.9.0 acorn@8.15.0
pnpm add chevrotain@^11.2.0
pnpm add @jsquash/jpeg @jsquash/png @jsquash/webp
pnpm add mathjs@12.4.3 ws@8.21.3 zod@^4.4.3
```

装完确认 `$NM/jsdom/package.json` 存在（依赖放在 profile 级也能被酒馆 host 解析，
Node 会从 `node_modules/dsh-tavern-host` 往上找到 `node_modules`）。

### 装法 2：电脑上装好再整体拷进设备

```bash
cd packages/dsh-tavern-host
pnpm install --prod          # 或 npm install --omit=dev
# 然后把 packages/dsh-tavern-host/node_modules 整个拷到
# $NM/dsh-tavern-host/node_modules
```

### 装法 3：已经有现成的依赖树（升级场景）

本机 `$NM/dsh-tavern-host/node_modules` 已经在就位时，安装器不会动它，
只覆盖代码文件。

> 依赖缺失不会让安装器失败，但酒馆打开后会报「服务端模板显示处理失败」，
> 正文退化成原文。用 `scripts/doctor.py` 能直接看到缺哪个。

## 2. 执行安装（方式 B）

把整个仓库放到设备上（例如 `~/Download/dsh-tavern-harmony`），然后：

```bash
cd ~/Download/dsh-tavern-harmony

python3 scripts/install.py            # 干跑：只打印计划
python3 scripts/install.py --apply    # 安装
```

可选参数：

| 参数 | 作用 |
| --- | --- |
| `--no-sidebar` | 不把 `dsh-better-sidebar` / `dsh-dream-skin` 加进 bundles（酒馆侧栏会缺） |
| `--no-core-patch` | 跳过核心 `dsh-llm-deepseek` 补丁（更费上下文，功能不受影响） |
| `--home PATH` | 指定 `$DSH_HOME`（默认从环境或设备常量推导，也可以设 `DSH_HOME`） |
| `--profile NAME` | profile 名，默认 `ondevice` |
| `--force` | 前置检查失败也继续（不推荐） |

安装器做的 6 件事（全部幂等）：

1. 复制 `packages/*` 到 `$NM/`（5 个包，跳过 `.bak` / `__pycache__`）
2. 给 `dsh-tavern-remote` 补 `zod`（从 host 的依赖里复制）
3. 渲染 `dsh-tavern-presets/cordis.patch.yml`（`{{CORE_DIR}}` / `{{PROFILE_DIR}}` → 真实路径）
4. 在 `$PROFILE/package.json` 的 `dsh.profile.bundles` 里登记
   `dsh-tavern-gate, dsh-better-sidebar, dsh-dream-skin, dsh-tavern-plugin, dsh-tavern-remote, dsh-tavern-presets`
   （插在最后一个 `@deepseek-ai/*` 之后，相对顺序固定）
5. 在 `$DSH_HOME/cordis.patch.yml` 补一条 `permission.defaultPreset: workspace-write`
   （已有 `- id: permission` 则不动）
6. 给核心 `dsh-llm-deepseek/lib/index.js` 打「酒馆会话不回放思维链」补丁（可用参数跳过）

写文件之前会备份到 `$DSH_HOME/_tavern-harmony-backup/<时间戳>/`。

技能不归安装器管：重启后由 `dsh-tavern-gate` 在启动时把 `dsh-tavern-gate/skills/` 同步到
`$DSH_HOME/skills/`（内容相同不写盘；不同先备份到 `$DSH_HOME/skills-backup/`）。

## 3. 重启并打开

1. **完全退出 DSHM**（从多任务列表里划掉，不是切后台），再打开。
   Host 只在启动时读 profile 与 bundle，不重启不生效。
2. 左下角出现「**酒馆：关**」。点它 → 按钮变「正在加载…」→ 页面刷新 → 酒馆界面。
3. 关掉：再点「酒馆：开」→ 刷新回原生界面。
4. 重启应用 = 回到关。

首次打开酒馆会创建 `$DSH_HOME/profile-data/tavern/`（人物卡、聊天等）。

## 4. 验证

```bash
python3 scripts/doctor.py
```

它会检查：包文件、profile 登记与顺序、依赖、preset 渲染与引用路径、
核心补丁、门的运行状态（`http://127.0.0.1:3120/api/tavern-gate/status`）、
开机标记、数据目录。全绿就说明装好了。

也可以直接看接口：

```bash
curl -s http://127.0.0.1:3120/api/tavern-gate/status
# {"loaded":false,"error":""}
```

## 5. 卸载

```bash
python3 scripts/uninstall.py             # 干跑
python3 scripts/uninstall.py --apply     # 摘掉代码与 profile 登记
python3 scripts/uninstall.py --apply --purge-data   # 连数据一起删（会先移到备份目录）
```

默认保留 `profile-data/tavern/`（人物卡、聊天、场景图）。
`--revert-core-patch` 会把核心文件从 `.bak-tavern-*` 还原。

## 6. 升级

```bash
# 用新版本仓库覆盖旧目录后
python3 scripts/install.py --apply
# 完全重启 DSHM
```

安装器会覆盖代码文件；`node_modules` 和酒馆数据都不动。重启后新的
`skills/` 也会同步过去。旧版本残留的多余文件
不会自动删除（`lib/**` 是整体覆盖，实践上没有影响）。想要干净升级：

```bash
python3 scripts/uninstall.py --apply     # 保留数据
python3 scripts/install.py --apply
```

## 常见安装问题

| 症状 | 处理 |
| --- | --- |
| 重启后没有左下角按钮 | bundle 没登记或没启用：`doctor.py` 看 ②；也可以在设置→插件 里确认 `dsh-tavern-gate` 是启用状态 |
| 按钮点了没反应 | 看 `$DSH_HOME/tavern-load.log` 的 `IMPORT FAILED` / `APPLY FAILED`，多半是依赖缺 |
| 打开了但正文重复/空白 | 模板引擎失败 → `doctor.py` 看 ③（jsdom） |
| 酒馆会话在原生界面打不开 | 开机会话补丁没装上：`DSH_TAVERN_BOOT_PATCH` 是否为 `0`，或 `tavern-load.log` 里有没有补丁失败 |
